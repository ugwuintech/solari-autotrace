# Handoff: AutoTrace UI redesign (completed) — context for the next task

Read `AGENTS.md` at the repo root first and follow it strictly. It defines the product
principles (evidence traceability, no fabricated sources, tests over parts replacement),
the architecture, and the rule to ask before installing any dependency.

## Project in one paragraph
AutoTrace (repo `solari-autotrace`, app code in `autotrace/`) is an automotive diagnostic
research agent. Input: vehicle + DTCs + symptoms. Pipeline (`autotrace/src/agent/investigate.ts`,
`runInvestigation`): build queries → Solari cloud browser research (DuckDuckGo + page
extraction) → structured evidence → hypothesis board H1–H5 → rule-based evidence polarity
(supports / contradicts / context; this layer is authoritative) → optional bounded round-2
follow-up research (max 2 rounds) → local Ollama/Qwen (`qwen3:4b`) assessment, validated
against a JSON schema and the collected evidence. Two front ends call the same pipeline:
the CLI (`npm start`) and a local web UI (`npm run dev`, `autotrace/src/ui/server.ts`).

## What was just done
The web UI was redesigned. Only these three files changed:
- `autotrace/src/ui/public/index.html`
- `autotrace/src/ui/public/styles.css`
- `autotrace/src/ui/public/app.js`

No backend, API, type or test changes were made, and no dependencies were added. The UI still uses
plain HTML/CSS/JS with no framework. The API contract is unchanged: a single blocking
`POST /api/investigate` with `{ vehicle, codes, symptoms }` returning `InvestigationUiResult`
(see `autotrace/src/types/ui.ts`, built by `autotrace/src/ui/mapInvestigationResult.ts`).
The user confirmed the new UI works against a real investigation.
The changes are **not committed yet**. The current branch is `main` (clean before this work).

### Design decisions (keep these unless the user asks otherwise)
- Instrument-cluster look: graphite background, a single amber accent (`--amber`),
  monospace for codes, IDs and URLs. All colours are CSS variables on `:root`.
  Deliberately no gradients, glow, glassmorphism or emoji.
- Polarity colours: green = supports, red = contradicts, slate = context.
- Two-column layout: the intake form on the left is sticky, the workspace on the right. Below 960px it stacks
  (`grid-template-columns: minmax(0, 1fr)`, which is needed to prevent horizontal overflow).
- The workspace has four states, switched by `showStage()` in app.js:
  idle → running → result | error.
- The result view order follows the UI concept in AGENTS.md:
  1. Case header: vehicle, code chips, and stats for rounds, evidence, open questions and model.
  2. Disclaimer.
  3. A `reassessmentError` warning, if present (the old UI ignored it).
  4. Hypothesis board: a qualitative support gauge, tallies of polarity mentions, and a `<details>` listing the sources.
  5. Evidence list: client-side filters All/Supports/Contradicts/Context, the source domain, and the original numbering kept when filtered.
  6. Assessment: model reasoning, labelled as model-written and separate from the evidence, plus open questions.
  7. Recommended next test: numbered procedure steps and the "Helps separate" hypotheses.
- The support gauge only echoes the qualitative label. It is not a probability, per AGENTS.md.
- The loading state shows a real elapsed timer, not fake stage progress, because the API
  does not stream progress. If you add progress reporting, it must reflect real
  pipeline events (e.g. SSE from the server), never simulated stages.

### Car animations (all SVG + CSS)
- Header logo: the sedan outline draws itself using a stroke-dashoffset animation.
- Idle: a parked car rolls in.
- Running: the car drives in place with wheels spinning at a speed matched to the scrolling lane dashes,
  a slight body bounce, a headlight beam, exhaust puffs and parallax roadside posts.
  Below it, a scrolling secondary-ignition scope trace generated by `scopePath()`.
- Error: the car stops with its hazard lamps blinking.
- `prefers-reduced-motion` disables all motion.

### Implementation gotchas
- The car SVG is injected by JS (`carSvg()` into every `[data-car]` element) rather than referenced with
  `<use>`, because CSS selectors and animations don't reliably reach into `<use>` shadow trees.
  Each copy gets a unique gradient ID.
- Wheels use an outer `<g transform="translate(...)">` with an inner `<g class="spin">`, because
  a CSS transform would override the SVG transform attribute.
- All API text is inserted through `escapeHtml()` / `sourceLink()`. Keep it that way.

## How the UI was verified
- `npm run typecheck` is clean, `npm test` shows 95/95 passing, and `node --check src/ui/public/app.js` passes.
- Visual check: a throwaway Node harness in the session scratchpad (not in the repo) served
  the real `public/` files and mocked the API with obvious placeholder data. Headless Chrome then
  captured the idle, running, error and result states.
  - Headless Chrome enforces a minimum viewport of about 512px, so for phone widths load the page in a
    375px `<iframe>` and measure there.
  - A mocked request that never responds stalls `--virtual-time-budget`. Use `--timeout` for
    the running state instead.
  - Never commit mock or placeholder investigation data to the repo.

## Constraints that still apply
- Ask before installing dependencies or introducing a frontend framework.
- Never fabricate evidence, sources or URLs in the UI or elsewhere.
- Keep secrets out of the repo. `autotrace/.env` is git-ignored, so never print its values.
- Commit or open a PR only when the user asks. Branch off `main` first.
- Report what changed, why, and how to test it, concisely.
